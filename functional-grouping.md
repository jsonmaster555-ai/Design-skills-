# Functional Grouping

Group controls and information according to what they accomplish, not merely because they fit in the same row or container.

Actions affecting the same object should generally appear together. Destructive actions should not be visually mixed with harmless navigation. Filters should form a coherent filtering region. Editing controls should remain distinguishable from viewing controls.

## Group strength

Use proximity first. Add separators, labels, or containers only when spacing alone cannot make the relationship clear.

## Action hierarchy

Within a group, distinguish primary, secondary, tertiary, and destructive actions. Do not give every action the same filled button treatment.

## Context

Keep actions near the content they affect. Avoid sending users across the interface to understand which control belongs to which object.

## Avoid toolbar dumping

Do not place unrelated actions into a single toolbar simply because horizontal space exists. Split groups by purpose and use spacing to expose those purposes.

Functional grouping should let users infer what controls belong together before they read every label.
